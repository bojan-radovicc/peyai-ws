Multi-Agent Cybersecurity Lab Authoring

A technical case study on building a multi-agent AI platform that automates the end-to-end authoring of cybersecurity training labs — from learning objectives to production-ready content, VM configurations, static challenge sites, and interactive web applications.

Industry Cybersecurity Education / EdTech
Scope Multi-Agent Orchestration, Content Generation, Infrastructure as Code, Web App Generation, Validation, Human-in-the-Loop Review
Tech Stack Python, Anthropic Claude API, AWS Step Functions, Lambda, S3, FastAPI, PostgreSQL, React, Docker, Pydantic, Pytest

Challenge

Creating high-quality cybersecurity training labs is time-consuming and requires coordination across multiple disciplines: curriculum design, infrastructure provisioning, web development, and security tooling. A single lab involves writing scenario narratives, configuring vulnerable environments, building challenge sites, and validating that every component aligns with the learning objective.

Manual authoring doesn't scale with the pace of new threat vectors and curriculum needs. Labs produced by different authors varied significantly in structure and quality, and updating existing content required touching multiple systems with no shared state between them.

Approach

  • Designed a multi-agent orchestration system where a planner agent decomposes a learning objective into a structured task graph for downstream specialist agents.
  • Built a curriculum agent that generates scenario narratives, step-by-step walkthroughs, hints, and solution guides with consistent pedagogical structure.
  • Built an infrastructure agent that produces VM configurations: network topology, installed packages, service bindings, and pre-seeded flags for capture-the-flag scenarios.
  • Built a web agent that generates static challenge sites and interactive web components (login forms, vulnerable endpoints, admin panels) matched to each lab scenario.
  • Added a validation agent that tests each artifact against the original objective, checks for internal consistency, and flags gaps before human review.
  • Implemented a human-in-the-loop checkpoint so instructors can approve, edit, or reject any stage output before the lab goes live.

Architecture & Data Flow

We structured the system as a directed agent graph, not a sequential pipeline. Agents that don't depend on each other run in parallel, which significantly reduces total authoring latency. All intermediate outputs are stored as durable artifacts, making every step resumable and auditable.

  • Instructor submits learning objective -> planner agent produces task graph
  • Curriculum agent + infrastructure agent run in parallel on their respective subtasks
  • Web agent consumes curriculum output to generate scenario-matched challenge sites
  • Validation agent runs cross-artifact checks: scenario consistency, flag placement, objective coverage
  • Human review gateway -> approved artifacts packaged and deployed to lab delivery system
  • Deployed labs served via CDN-backed static hosting with isolated VM environments per learner

Technical Decisions & Reasoning

1) Why multi-agent instead of a single large prompt?

A single prompt over the full lab specification produces outputs that are hard to validate, debug, and iterate on. Specialized agents with bounded scopes produce smaller, typed outputs that can be checked against schema, tested independently, and retried without rerunning the whole workflow. Agent specialization also improves output quality: each agent is prompted and tuned for one task.

2) How we handled inter-agent state and shared context

Each agent reads from a shared artifact store (object storage) keyed by lab ID and stage name. Agents receive their inputs as structured documents — not raw chat history — which keeps context focused and reduces prompt bloat across long workflows. The planner produces a manifest that acts as the ground truth for what each downstream agent needs to produce.

3) Managing partial failures in the agent graph

Agent failures are isolated: if the web agent fails, curriculum and infrastructure outputs are preserved and the web agent can be retried without restarting the full graph. We track per-stage completion state in a metadata table, enabling selective reruns and progress inspection without losing work. Failure reasons are logged with enough context for debugging.

4) Validation strategy: automated checks + human review

Automated checks cover structural completeness (required fields, valid flag formats, reachable service ports) and objective coverage (does the curriculum mention each required concept?). These catch most mechanical errors before human review. Human review focuses on accuracy, pedagogical soundness, and scenario realism — tasks where instructor judgment adds the most value.

5) Reproducibility and lab versioning

Every lab generation run is logged with the exact model versions, prompts, and parameters used. Lab artifacts are versioned in object storage, so instructors can compare outputs across runs and roll back to previous versions without data loss. This makes the authoring process auditable and supports iterative improvement of prompt templates over time.

Outcome

The platform replaced a multi-day, multi-person manual authoring process with an automated workflow that produces a complete lab draft in under two hours. Human review time dropped significantly because validation agents catch structural issues before instructor review. The system now supports consistent lab production across multiple cybersecurity domains.

Next Steps

  • Active-learning loop: use instructor edits to improve prompt templates and agent behavior over time.
  • Adaptive difficulty: generate lab variants at beginner, intermediate, and advanced levels from a single objective.
  • Lab freshness scoring: automatically detect when a lab's scenario becomes outdated relative to current threat intelligence.
  • Learner telemetry integration: feed completion rates and stuck-point data back into curriculum agent to improve hint quality.
