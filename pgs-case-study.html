Vehicle Routing Optimization Engine

Back to Projects

A deep technical case study on how we built a production-ready routing engine to turn noisy weekly logistics inputs into feasible, cost-aware delivery plans with measurable efficiency gains.

Challenge

Weekly route planning started from raw operational exports that were difficult to optimize consistently. Manual planning created variability in route quality, overused certain truck types, and made deadline feasibility hard to validate at scale.

The key technical bottleneck was geospatial computation: once you have hundreds of stops, pairwise distance/time lookups grow quickly and API calls become expensive and rate-limited. We needed an approach that remained accurate, scalable, and financially sustainable.

Approach

  • Built a CLI orchestration pipeline to run end-to-end jobs (transform raw data, build geo lookup, optimize, calculate stats, generate reports, export routes).
  • Separated concerns between map services: ORS for matrix/distance fidelity and OSRM for route geometry visualization.
  • Implemented cache-first geo lookup persisted in CSV so expensive pair computations are done once and reused across all optimizer iterations.
  • Designed a VRP ALNS solver with strict capacity and deadline feasibility rules, plus greedy repair for practical convergence.
  • Made optimization business-aware by using route money-cost objective (tiered pricing, stop-based costs, additional route fees), not only distance minimization.

Architecture & Data Flow

We process raw weekly inputs into structured artifacts first, then optimize from standardized domain models. This reduced edge-case handling inside the solver and made the system testable in layers.

  • Raw route dump -> structured weekly files
  • Unique stops -> geo pair generation -> distance/duration lookup cache
  • Weekly optimization via VRP ALNS -> optimized routes in source-of-truth JSON
  • Stats + cost calculation -> weekly KPI outputs
  • Map and report generation -> operational review + Excel export

Technical Decisions & Reasoning

1) Why ORS + OSRM instead of one provider?

We wanted robust route metrics for optimization and lightweight geometry rendering for reporting. ORS gives strong matrix capabilities for computational steps, while OSRM is practical and cost-effective for generating polyline geometry in map views. This split keeps optimization quality high without making every visual operation paid-API dependent.

2) Handling combinatorial growth in geo pairs

Distances between many stops can explode toward O(n²) relationships. Recomputing these pairs every run is not feasible. We solved this with:

  • deduplication of destination pins before matrix requests,
  • batch matrix requests instead of one-call-per-pair,
  • serialized lookup caching so future runs are mostly local reads.

3) Cost control under API limits

To avoid unnecessary premium usage, our strategy is to minimize API calls first (cache + batching), then distribute request pressure safely. A practical extension is API-key round robin across a managed key list, with per-key throttling and backoff. This keeps request volume smooth, reduces sudden quota exhaustion, and delays the need for higher paid tiers.

4) Why ALNS for optimization?

ALNS gave us a strong trade-off between implementation complexity and performance for multi-truck VRP. The destroy/repair pattern is flexible enough for real constraints, and with fast feasibility checks (capacity + deadline-aware insertion), it scales better than naive exhaustive search while still producing high-quality weekly plans.

Outcome

The result is a repeatable optimization engine that replaced ad-hoc planning with deterministic, explainable, and measurable routing decisions. Across benchmark weeks, optimized solutions consistently improved key operational and cost metrics versus manual baselines.

Total Route Distance -30.1%

Lower cumulative distance across benchmark weeks with optimized stop sequencing and assignments.

Total Route Time -28.7%

Reduced driving time while preserving route feasibility under real delivery deadlines.

Estimated Routing Cost -29.3%

Modeled cost reduction using tier-aware route pricing and fleet-aware planning decisions.

Next Steps

  • Adaptive key rotation policy with health checks and automatic cooldown handling.
  • Incremental geo-cache updates for new stops only (instead of broad rebuilds).
  • Scenario-based optimization (cost-first, time-first, SLA-first profiles).
